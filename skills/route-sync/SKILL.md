# 路由同步

维护路由 wiki 与契约文档同代码现状的一致性。职责包含：首次创建、日常同步、自检（lint）与遗留结构迁移。仅在确认变化时修改；确认变化但部分信息未知时，只更新已确认部分并将未知标为 `uncertain`。

## 核心原则

- 路由 wiki 是指针网络，不是代码索引或知识库：页面只回答"下次提到某个词汇，先读哪些代码与契约"。实现细节以代码为准，约束以契约文档为准，页面不复制两者内容。
- 页面承接任意角度词汇：业务场景建功能页，架构与技术场景建机制页；同一概念只有一个页面。
- 硬预算：路由页正文 ≤ 12 行、字段限于白名单；index 每页恰一行。预算是 lint 判定项，不是建议。
- 更新优先、建页克制：优先更新既有页面；仅当确认出现无页面承接的重要概念时才建新页，并同步 index 与 log。
- 实际代码变更优先于规划文档。
- 默认只改与当前任务相关的页面；不为风格一致重写整个 wiki。
- 无法确认的信息标 `uncertain` 或省略——绝不臆造。
- 默认只改 wiki、log 与契约文档，不改业务代码。
- 契约与代码不一致时不得静默偏移：改代码回归契约，或显式修订契约，由用户裁决。

## 路由 wiki 结构

- 位置：`docs/routespec/wiki/`，含 `index.md`、路由页与 `log.md`。
- `index.md` 是唯一查询入口，单文件不分片：每个页面恰占一行，按「业务功能」「技术机制」两组 `##` 分节，行格式：

```
- [[页面名]] —— 一句话；关键词：最强别名
```

- 路由页以 kebab-case 命名，正文 ≤ 12 行，字段白名单：别名 / 说明 / 核心 / 契约 / 相关：

```md
# {页面名}

- 别名：{用户与代码中可能的其他说法，含标识符名}
- 说明：{一句话}
- 核心：`path/to/file`（1-3 个起步阅读点）
- 契约：`docs/integration/{name}.md`（可选，0-n）
- 相关：[[{page}]]（可选，≤4）
```

- 页面不设覆盖、last-updated 等扩展字段；健康度由 log 与 lint 承担。
- `log.md` 为 append-only 单行日志，仅记 miss / sync / lint 三类：
  - `[yyyy-MM-dd] miss | "{词汇}" | resolved→[[{页面}]] / unresolved`
  - `[yyyy-MM-dd] sync | {页面名}: {一句话动作}`
  - `[yyyy-MM-dd] lint | {n} fixed, {m} open: {一句话}`

## 契约文档

- 位置：`docs/integration/`，kebab-case 命名。
- 收录范围——代码不可直接推导、必须显式遵守的约束：
  1. 跨端协议契约：帧/事件/字段语义、时序、错误码。
  2. 接口契约：对外 API 兼容性承诺、版本与废弃策略。
  3. 数据契约：落库字段语义、时间/编码规范、迁移与兼容约束。
  4. 架构边界：模块职责边界、依赖方向、禁改区。
  5. 隐式约定：代码不可见的默认行为、魔法值含义、环境与启动依赖。
  6. 术语定义：业务词汇与代码概念的对应，兼作页面别名来源。
- 排除：实现描述（代码为准）、单端内部逻辑、代码可直读的结构、通用工程常识。
- 写作规则：条款化编号；只写"是什么 / 必须遵守什么"，不写"怎么实现"；标注生效范围（涉及端/模块）；同一契约唯一权威文档，他处引用不复制。
- 生命周期：契约新增与修订随任务进行——`spec` 判定影响，变更先契约后代码；本技能保持页面 `契约` 字段与实际文档一致，并执行孤儿契约检查。

## 何时检查

以下情况检查同步，且仅在确认变化时修改：

- 核心功能或机制新增、删除。
- 页面锚定的核心文件改名、移动或替换。
- 契约文档新增、修订或废止。
- log 中存在 resolved 的 miss 待回填。
- wiki 结构影响当前任务定位。

以下情况通常只需说明理由：内部实现细节调整、格式与注释、不影响起步阅读点的小重构、不影响契约的补测试。

## 工作流程

1. 读 `docs/routespec/wiki/index.md`。不存在而 `docs/routespec/feature-routes/README.md` 或 `docs/routespec/feature-routes.md` 存在时，按"迁移指南"处理；都不存在且当前任务需要代码定位时，转"首次创建模式"。
2. 收集当前任务信息：实际改动文件（或 `git diff`）、测试结果、执行摘要、`spec.md`、用户说明、log 中的 miss 记录。
   - 实现未完成或验证失败时，只同步已确认部分；未验证路径标 `uncertain`，不得输出确定的"已更新"。
3. 判定动作：
   - 不需要：输出理由，不改文件。
   - 更新页面：修改字段（别名 / 说明 / 核心 / 契约 / 相关）。
   - 新建页面：确认无既有页面承接该概念后建页。
   - 修订契约：按"契约文档"写作规则修改 `docs/integration/` 下对应文档。
   - 回填别名：把 log 中 resolved 的 miss 词汇补进对应页面 `别名`。
4. 执行硬预算：任何写入先对照页面模板与行数预算；超容内容分流——实现细节归代码（不落盘）、约束归契约文档、过程归任务档案，页面只留指针。
5. 同步 index 与 log：新页加行、改名改行、删页删行；追加 sync 行。
6. 顺手执行 lint，修复可修项，遗留项记入 log 与摘要。
7. 输出同步摘要。

## 自检（lint）

每次同步顺手做近零成本检查；用户要求检查 wiki 健康度时，展开为逐项全面体检。共九项：

防过时：
1. `核心` 引用的源码文件存在（覆盖改名、移动、删除）。
2. `契约` 引用的 `docs/integration/` 文件存在。
3. 近期任务大量触碰某 `核心` 文件而对应页面未同步的，复核该页是否仍指向最值得先读的位置。

防冗余：
4. 页面预算：正文 ≤ 12 行、字段在白名单内、无段落式实现描述。
5. 索引一致：每个页面文件在 index 恰有一行，index 每行有对应页面文件。
6. 孤儿页：存在不在 index 的页面（不可发现，必须修）。
7. 重复页：两页别名或核心高度重叠时合并为一页，index 行与 `相关` 链接同步更新。
8. 未回填 miss：log 中 resolved 的 miss 词汇未出现在任何页面 `别名`。
9. 孤儿契约：`docs/integration/` 下文件无任何页面、AGENTS.md 或 README 引用。

结构问题就地修复；语义存疑标 `uncertain` 并写入摘要。除非用户显式要求全面审计，不做逐页全量体检。

## 首次创建模式

触发条件：路由 wiki 不存在（`docs/routespec/wiki/index.md` 不存在且无遗留结构），当前任务需要代码定位。

1. 针对当前任务做有针对性扫描：优先源码、入口、配置与测试目录；排除依赖、构建产物、缓存与生成代码。
2. 创建 `index.md` 与当前任务能确认的页面（功能页、机制页皆可），不追求覆盖面。
3. 当前任务存在代码不可推导的约束时，创建对应 `docs/integration/` 契约文档并在页面 `契约` 字段引用。
4. 创建 `log.md`。
5. 回到 `route-lookup` 继续查询流程，覆盖状态记为 `partial`。

## 迁移指南

发现 `docs/routespec/feature-routes/` 目录或 `docs/routespec/feature-routes.md` 单文件时，按 `references/migration.md` 收敛到当前结构；默认只迁移与当前任务相关的部分。

## 输出格式

```md
# 路由同步摘要

## 结果
- 已更新 / 无需更新 / 部分 / 不确定

## 页面变更
- 新增：无 / [[page]]（理由）
- 修改：无 / [[page]]：变更内容
- 合并：无 / [[a]] + [[b]] → [[c]]
- 删除：无 / [[page]]（理由）

## 契约变更
- 无 / 新增：`docs/integration/...` / 修订：`docs/integration/...`（条款号与内容）

## 别名回填
- 无 / [[page]] ← "{词汇}"

## 索引与日志
- index：已同步 / 无变化
- log：已追加 / 无变化

## lint 结果
- 通过 / 已修复：... / 遗留：...（处理建议）

## 未确认内容
- 无 / ...

## 后续建议
- 无 / ...
```

# 路由同步

维护功能路由图与当前代码位置信息的一致性。职责包含：首次创建、日常同步、审计、主动补全（harvest）、轻量 drift 自检与遗留结构迁移。仅在确认位置信息变化时修改文档；确认变化但部分字段未知时，只更新已确认信息并将未知字段标为 `uncertain`。

## 核心原则

- 功能路由图不是完整代码索引或功能知识库，只记录"下次改某个功能时，最值得先读的位置"。
- 分层始终以业务与功能为维度组织，不按技术分层或目录结构组织。
- 条目只标注核心源码文件；模型读取核心源码后自然会扩散访问其余相关代码，不穷举入口、页面、API、命令与所有实现文件。
- 实际代码变更优先于规划文档。
- 无法确认的信息标为 `uncertain` 或直接省略——绝不臆造。
- 默认只修改相关条目；不为风格一致而重写整张路由图。
- 若路由图结构影响当前任务定位，允许局部结构调整：补充 README 索引、把相关条目归到对应业务域、拆分过大的域文件；不为风格一致重写无关条目。
- 默认只改 RouteSpec 文档，不改业务代码。

## 何时检查

以下情况需检查路由同步，且仅在当前任务确认位置信息变化时修改路由图：

- 核心功能新增或删除。
- 功能入口文件变更。
- 核心实现文件迁移。
- 关键测试入口新增、删除、迁移或重命名。
- 路由图明显过时。
- 路由图缺失业务域层级，导致当前任务无法通过业务域或功能稳定定位。

以下情况通常只需说明为何不必修改：内部实现细节调整、格式、注释、通用文案、日志、不改变定位路径的小重构、以及不影响关键测试入口的补测试。

## 工作流程

1. 读取功能路由图唯一入口：`docs/routespec/feature-routes/README.md`。README 不存在而 `docs/routespec/feature-routes.md` 存在时，读取该文件继续同步，并按"迁移指南"处理；两者都不存在且当前任务需要代码定位时，转"首次创建模式"。
2. 收集当前任务信息：实际改动文件、`git diff`、测试结果、执行摘要、`spec.md`、用户说明。
   - 若实现未完成或验证失败，只同步已确认的位置变化；存在未验证路径时须标 `uncertain`——不得输出确定的"已更新"。
3. 判定是否需要修改：
   - 不需要：输出理由，不改文件。
   - 需要：更新既有功能定位条目，或新增功能定位条目。
   - 不确定是否变化：不改文件，只输出未确认内容。
   - 确认变化但部分字段未知：更新已确认信息，未知字段标 `uncertain`。
4. 处理废弃或移除的功能：
   - 功能仍存在但不推荐：在备注中标注 deprecated。
   - 功能已删除或被替换：删除或移动相关定位条目；需保留时只记原条目与替换功能。
   - 仅当用户显式要求整理归档时才移至 `feature-routes-archive.md`。
5. 修改内容应与既有路由图条目格式保持一致；如需结构调整，按"README 入口 → 业务域 → 功能"层级更新相关区域。
6. 结构调整时，只处理与当前任务确认相关的业务域与功能；归属未确认的条目标 `uncertain` 或保持原位。
7. 在触碰的条目上顺手维护可选的 `覆盖` 字段（sufficient / partial / missing），把 route-lookup 阶段判定的覆盖状态持久化，使路由图健康度跨任务可追踪。
8. 输出同步摘要。

## 路由图结构

- 位置统一为 `docs/routespec/feature-routes/` 目录，`README.md` 是唯一必读入口：查询方始终只读这一个路径即可完成定位，无需探测其他文件或目录是否存在。
- README 两种形态：
  - **内联形态**（小工程或条目很少）：概览与全部业务域、功能条目直接写在 `README.md` 内。
  - **索引形态**（中大型工程或有清晰业务域）：`README.md` 只保留概览与"业务域 → 路由文件"索引，条目拆到域文件。
- 域文件按业务域用 kebab-case 命名，如 `feature-routes/trade-order.md`；域文件内用"子业务域（`##`）→ 功能（`###`）"两级标题承载多层级业务；单个域文件过大时才拆子文件并在 README 索引中指向，不预设更深层级。
- 分层始终以业务、功能为入口：顶层是业务域（如交易、履约、用户），不是技术层（controller/service）或目录结构；本身即独立产品的技术组件（如网关、CLI、开放平台）可视为业务域。
- 多代码库工作区中，路由图相对各代码库根独立建立与维护。

## 初始模板

README 内联形态：

```md
# 功能路由图

## 概览

- 应用：...
- 主入口：`...`

## {业务域}

### {功能名}

- 描述：...
- 核心：`path/to/core/file`
- 备注：...（可选）
```

README 索引形态：

```md
# 功能路由图

## 概览

- 应用：...
- 主入口：`...`

## 路由索引

- {业务域}：`{file}.md` —— {该域覆盖功能的一句话说明}
```

域文件：

```md
# {业务域}

## {子业务域}（可选）

### {功能名}

- 描述：...
- 核心：`path/to/core/file`
- 备注：...（可选）
```

初始化时即便只确认了少量信息，也可保留层级结构；缺失字段可省略，不强写 `N/A`。

## 功能定位条目

每个功能只保留有助定位的最少信息：

- 功能名（标题）。
- 一行描述。
- 核心：核心源码文件（1-2 个）。只列源码文件——模型读取核心源码后自然会扩散访问其余必要代码；用户入口、页面、API、命令、配置、数据与持久化位置一律不单列，确有定位价值时并入备注。
- 备注（可选）：关键测试/验证入口、deprecated、与其他功能的强联动等确实影响定位的信息，尽量一条。

状态、类型、变更历史、平台差异、可观测/调试等扩展信息不写（可选的 `覆盖` 与 `last-updated` 字段除外，见"可选字段"）；确实影响定位时合并为一条备注。

## 可选字段

- 条目可选 `覆盖` 字段（sufficient / partial / missing）：由本技能在触碰条目时维护，承接 route-lookup 的覆盖判定。
- 条目可选 `last-updated: <任务目录或日期>`：便于把任务文档与路由图条目双向溯源，防止两边分叉。
- 这些字段为可选；既有条目无需回填，新增条目建议带上。

## 主动补全（harvest）

当某业务域覆盖长期为 `partial` 且影响后续定位时，可在用户确认下主动补全该域条目，而非永远被动等待"确认变更"：

- 仅记录有助定位的信息；无法确认的字段标 `uncertain` 或省略。
- 补全范围限定在被确认相关的业务域；不扩散到无关域。
- 中大型项目里路由图价值兑现慢，主动补全是加速路由图"长到够用"的手段。

## 默认轻量 drift 自检

每次同步顺手做近零成本检查（不展开为逐条全面审计）：

1. `核心` 引用的源码文件是否存在。
2. 条目是否仍指向最值得先读的核心源码；明显偏离时标 `partial`。
3. 备注中的关键测试/验证入口文件是否存在、是否仍是该功能的关键验证入口。
4. 是否存在功能删除、迁移或核心实现重命名但未反映到路由图。
5. 每个条目是否至少含一个可用的核心源码位置。
6. 索引形态下，README 索引与实际域文件是否一致（缺域、多域、指向失效）。
7. 顶层是否混入技术分层或目录结构维度的域；发现时只调整与当前任务相关的域。

发现关键定位信息缺失时，结果标 `partial` 并按本技能正常流程补充已确认信息。其余问题按正常流程更新。除非用户显式要求全面审计，不进入复杂审计流程。

## 审计模式

当用户要求检查路由图是否过时时，先做轻量审计。默认只查与当前任务相关的业务域；仅当用户显式要求全面审计或全量检查时才逐条核对所有功能定位条目（即上文 drift 自检的 7 项，逐条展开）。全部通过则输出"无需更新"；发现缺失关键定位信息时标 `partial` 并按正常流程补充。

## 迁移指南

发现 `docs/routespec/feature-routes.md` 单文件，或目录缺少 `README.md` 入口/索引时，按 `references/migration.md` 迁移到当前结构；默认在下一次同步时只迁移与当前任务相关的部分，不做一次性全量重写。

## 首次创建模式

触发条件：功能路由图不存在，且当前任务需要代码定位。

1. 确认路由图不存在：检查 `docs/routespec/feature-routes/README.md` 与 `docs/routespec/feature-routes.md` 均不存在。
2. 基于当前任务做有针对性扫描，优先源码、入口、配置与测试目录；排除依赖、构建产物、缓存与生成代码。
3. 创建 `docs/routespec/feature-routes/README.md`：条目少或业务域尚不清晰用内联形态；业务域清晰或条目预计快速增长用索引形态，并同步创建与当前任务匹配的域文件。
4. 当前任务能关联到清晰业务域、功能或核心源码时，至少写一条功能定位条目；不适合生成条目时只保留基础模板并说明理由。
5. 初始化完成后，回到 `route-lookup` 继续查询流程，覆盖状态记为 `partial`。

## 输出格式

```md
# 路由同步摘要

## 结果
- 已更新 / 无需更新 / 部分 / 不确定

## 新增功能路由
- 无 / ...

## 修改功能路由
- 无 / ...

## 废弃或移除
- 无 / ...

## 文件位置变更
- 无 / ...

## 结构调整
- 无 / 补充 README 索引 / 条目归入业务域 / 拆分域文件 / 迁移遗留结构 / ...

## 覆盖状态持久化
- 已更新覆盖字段的条目：无 / ...

## 未确认内容
- 无 / ...

## 后续建议
- 无 / 建议人工确认 / 建议再次运行 route-sync 审计 / ...
```

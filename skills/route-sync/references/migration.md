# 路由图迁移指南

把两类遗留形态迁移到当前结构。当前结构：`docs/routespec/feature-routes/` 目录 + `README.md` 唯一入口 + 业务/功能分层 + 条目只标核心源码。

## 遗留形态 A：单文件 `docs/routespec/feature-routes.md`

1. 创建 `docs/routespec/feature-routes/README.md`。
2. 按业务域重组既有模块与条目：
   - 模块名即业务域的直接沿用。
   - 按技术分层或目录结构命名的模块，按其承载的业务重新归组；归属不清的条目集中放入一个"未归类"域并在备注标 `uncertain`，不猜测归属。
3. 条目字段收敛：入口、测试等定位字段收敛为"核心 + 备注"；`核心` 只保留核心源码文件（1-2 个）。
4. 条目总量少时全部内联进 README；条目多或业务域清晰时 README 做索引、条目拆到域文件。
5. 分批迁移时，把本次已迁移的条目从旧 `feature-routes.md` 中移除，未迁移部分保持原位；确认新结构覆盖旧文件全部条目后，删除旧 `feature-routes.md`，避免双份分叉。
6. 迁移后覆盖状态标 `partial`，由后续任务逐步补全。

## 遗留形态 B：目录缺 README 入口

表现：`docs/routespec/feature-routes/` 存在但没有 `README.md`（或索引写在 `index.md`）。

1. 创建 `README.md` 为入口：条目总量少时把散文件条目并入 README（内联形态）；条目多时 README 做"业务域 → 路由文件"索引。
2. 索引写在 `index.md` 的，把索引内容并入 README 后删除 `index.md`——入口必须唯一。
3. 散文件按业务域归位、重命名为 kebab-case，并核对文件内层级为"子业务域（`##`）→ 功能（`###`）"。

## 分批原则

- 默认在下一次 route-sync 时只迁移与当前任务相关的业务域；未迁移部分保持原位，由后续任务逐步收敛。
- 不做一次性全量重写；仅当用户显式要求时才全量迁移。
- 迁移只调整结构与定位字段，不借机重写条目内容。

## 多代码库工作区

- 每个代码库独立迁移自己的路由图；跨库任务目录（collaboration.md）不属于路由图，不参与迁移。

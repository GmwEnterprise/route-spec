# 路由 wiki 迁移指南

把遗留形态收敛到当前结构。当前结构：`docs/routespec/wiki/`（`index.md` + 路由页 + `log.md`）＋ 契约文档 `docs/integration/`。

## 遗留形态 A：`feature-routes/` 目录（README + 域文件）

按收缩式收割迁移：

1. 逐条目提取三样：页面名（沿用条目名或重命名为更贴近词汇的 kebab-case）、核心文件、可提炼别名——条目描述与备注中的业务/技术词汇、代码标识符。
2. 建路由页：遵守 ≤ 12 行预算与字段白名单；多个条目指向同一概念时合并为一页。
3. 正文分流：
   - 实现性描述（状态机、流程、字段清单等代码可查内容）直接弃，以代码为准。
   - 确属代码不可推导的约束（协议语义、兼容承诺、隐式约定等）改写为条款式，落入 `docs/integration/` 对应契约文档，页面 `契约` 字段引用。
4. 旧业务域文件名不保留为分组维度；index 按功能页 / 机制页重组，每页一行。
5. 分批迁移：默认只迁移与当前任务相关的域；未迁移部分保持原位，route-lookup 以旧结构回退读取（覆盖标 `partial`）。
6. 确认全部条目收敛后删除旧目录，避免双份分叉。

## 遗留形态 B：单文件 `feature-routes.md`

先按条目拆分，再按形态 A 收割。

## 契约文档初始化

- 旧条目中的契约价值段落按形态 A 第 3 步分流改写；不逐条搬运，只处理确认仍生效的约束。
- 既有 `docs/integration/` 文档保持原位，作为权威契约被页面引用；与代码不一致的按"先契约后代码、冲突交用户裁决"处理，不在迁移中静默改写。

## 分批原则

- 默认在下一次 route-sync 时只迁移与当前任务相关的部分；未迁移部分保持原位，由后续任务逐步收敛。
- 不做一次性全量重写；仅当用户显式要求时才全量迁移。
- 迁移只做指针收敛与约束分流，不借机重写语义。
